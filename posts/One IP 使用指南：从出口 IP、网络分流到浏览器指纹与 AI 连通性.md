## 前言

平时排查网络问题，我经常要在几个工具之间来回切换：先查当前 IP，再检查网站是否经过代理，接着看 AI 平台有没有故障。如果同一网络下只有某个浏览器不能用，还得继续检查扩展、权限和浏览器环境。

这些检测单独做都不复杂，麻烦的是结果分散，放在一起又容易混淆。比如 IP 查询显示的是某次请求的出口，全球 Ping 测的是远程机器到目标的路径，它们回答的其实是不同的问题。

于是我把日常用到的检测整理成了 [One IP](https://ip.huzhihui.com/)。这篇既是网页使用说明，也是 API 接入指南：前半部分结合场景说明检测步骤与结果含义；后半部分介绍如何在服务器上查询出口或指定 IP，如何用 Node.js、Python 读取结果，以及如何通过自己的接口把结果直接返回给调用方。只想接入 API，可以从后面的 API 章节开始。

- 在线使用：[ip.huzhihui.com](https://ip.huzhihui.com/)
- 开源代码：[GitHub / one-ip](https://github.com/zhihui-hu/one-ip)
- 接口说明：[API 使用](https://ip.huzhihui.com/docs/api)
- 问题反馈：[ip@huzhihui.com](mailto:ip@huzhihui.com)

> 网页部分基于 2026 年 9 月整理的页面说明，API 示例于 2026 年 10 月 15 日核对。“分流出口”已合并到“网站连通与出口”，旧入口会跳转。文中截图来自此前版本，用于认识页面布局；按钮位置与功能名称以当前页面为准。

## 快速开始：完成一次基本检查

### 打开网站，找到需要的工具

用电脑或手机浏览器打开 [One IP](https://ip.huzhihui.com/)。电脑端通过页面导航切换功能，手机端通过底部导航进入对应分类，再选择分类里的工具。

网站主要分成五个入口：

| 入口       | 主要用途                                         | 什么时候用                       |
| ---------- | ------------------------------------------------ | -------------------------------- |
| 概览       | 集中看当前网络与浏览器的主要结果                 | 第一次检查、切换网络后快速对照   |
| 网络检测   | 查 IP、检查网站响应、DNS、CDN、WHOIS 和全球 Ping | 怀疑出口、分流或网络线路有问题   |
| AI 检测    | 查看 AI 平台资源响应与部分出口信息               | 某个 AI 网站慢、打不开或使用异常 |
| 服务状态   | 查看厂商公开的故障与维护信息                     | 想确认是否是服务商正在出问题     |
| 浏览器检测 | 查看环境、指纹、权限及相关检测信号               | 同一网站在不同浏览器里表现不同   |

![One IP 桌面概览，包含出口信息、网络连通性与 AI 服务状态](https://img.huzhihui.com/2026/09/11/desktop-home-redacted.webp)

截图已经遮盖 IP、位置和运营商信息。截图里的延迟、颜色和状态是当时的结果，不是你打开网站后应该得到的“标准答案”。

### 先看出口，再看网站响应

进入概览后，检测结果会逐步出现。先等待当前区域完成加载，向下滚动查看其他区域。部分网站检测会在对应内容进入可见区域后开始，刚打开页面时看到等待状态，不一定是卡住了。

第一次只需要关注两件事：

1. **有没有查到公网出口 IP。** 有结果就先记住地址及其来源，不用急着理解所有字段。
2. **常用网站有没有返回响应。** 多个目标都失败，与只有一个目标失败，后续排查方向不同。

没有代理、只是想了解自己的网络，到这里已经完成了基础检查。如果还想知道某个网站为什么不能用，再进入后面的对应章节。

### 修改前后各测一次

有了第一轮结果，接下来就可以做对比了。这里我更建议保留修改前的结果，再调整一个条件重新检测。这样至少能知道，这次变化与哪一步操作有关。

例如想检查代理是否生效，可以先记录当前结果，接着只打开代理，再刷新页面观察。不要同时换 Wi-Fi、换浏览器、换节点，否则结果虽然变了，却不知道是哪一步起了作用。

可以简单记录：

```text
检测时间：
使用设备和浏览器：
当前网络：家里 Wi-Fi / 公司网络 / 手机流量
代理状态：关闭 / 开启，当前节点或策略
检测目标：
修改前的出口和结果：
本次只修改了什么：
修改后的出口和结果：
```

这个记录留给自己排查即可。公开发截图或求助时，再遮盖 IP、指纹标识和具体位置信息。

## 使用前，先认识几个常见概念

接下来会用到 IP、分流、延迟等概念。我们先把它们放在一起说明，后面再结合实际结果来看。不需要记住缩写，阅读某个功能时回来查就可以。

| 词语           | 用简单的话解释                             | 举例或注意点                                         |
| -------------- | ------------------------------------------ | ---------------------------------------------------- |
| IP 地址        | 网络通信中使用的地址                       | `1.1.1.1` 是 IPv4 的一种写法                         |
| 公网出口 IP    | 这次请求到达目标服务时，对方看到的来源地址 | 使用代理后，对方可能看到代理服务器的地址             |
| 内网 IP        | 家庭、公司等局域网内部使用的地址           | 路由器里的 `192.168.1.10` 通常不是网站看到的公网出口 |
| IPv4 / IPv6    | 两种 IP 地址格式                           | IPv4 常见点分数字，IPv6 常见冒号分隔的字符           |
| 域名           | 便于记忆的网站名称                         | `ip.huzhihui.com`，不包含 `https://`                 |
| 代理、节点     | 请求经过的中转服务及其连接位置             | 不同目标是否经过中转，取决于配置                     |
| 分流           | 按目标决定请求走哪条路径                   | 一部分网站直连，另一部分经过代理                     |
| 延迟、ms       | 一次测量花了多长时间；ms 是毫秒            | `1000 ms` 等于 1 秒，延迟不是下载速度                |
| ISP            | 网络服务提供方或运营商                     | 可能是宽带运营商，也可能是云服务商                   |
| ASN            | 管理一组网络路由的自治系统编号             | 用来辅助识别网络归属，不是个人身份编号               |
| 未知、暂不可用 | 本次没有拿到足够信息                       | 不等于正常，也不一定等于故障                         |

另外，“查询一个 IP”和“使用这个 IP 上网”是两回事。你在输入框查询 `1.1.1.1`，只是查看这个地址的信息，不会把自己的出口改成它。

## 公网出口：确认请求从哪里出去

入口：[概览](https://ip.huzhihui.com/)。

先来看最常用的出口查询。我们打开网页时，目标服务会收到一次连接，而公网出口 IP 就是它看到的来源地址。这个地址可能属于家庭宽带，也可能属于请求经过的代理服务器。

### 基本用法

1. 打开概览，等待 IP 相关区域返回结果。
2. 查看结果来自哪个探测来源，再看它返回的地址。
3. 记录地址、国家或地区、运营商等信息。
4. 如果要比较网络变化，只切换一个条件，例如从 Wi-Fi 切到手机流量，再刷新检测。

### 为什么会看到不止一个 IP

前面查到地址后，可能会发现几个来源给出的结果并不相同。来看看一个简单的过程：浏览器分别访问网站 A 和网站 B，A 告诉我们它看到的来源地址，B 也返回自己的观察结果。假如 A 直连、B 经过代理，两边返回不同地址就符合这条请求路径。

常见情况包括：

- 网站 A 直连，网站 B 经过代理，两者看到不同出口。
- IPv4 经过代理，IPv6 走另一条路径，两种地址的网络归属不同。
- 浏览器扩展只代理网页流量，其他类型的连接没有经过同样的路径。

也就是说，出口要和目标一起看。排查某个网站时，我们关心的是访问它的请求走哪条路径，而不是先从所有结果里选出一个地址，再要求其他结果与它一致。

### 常见结果怎么处理

| 看到的情况                 | 可以先怎么理解                       | 下一步                       |
| -------------------------- | ------------------------------------ | ---------------------------- |
| 地址与路由器里显示的不一样 | 内网地址与公网出口可能本来就不同     | 先确认比较的是不是同一种地址 |
| 打开代理后部分出口变化     | 可能正在按规则分流                   | 到“网站连通与出口”核对目标   |
| 查询城市与实际城市不一致   | 数据库归属可能有偏差或更新延迟       | 结合其他来源及运营商信息判断 |
| 没有 IPv6 结果             | 当前路径或探测没有获得 IPv6 数据     | 先看 IPv4 和实际网站能否使用 |
| 某个来源一直没有结果       | 该来源可能受超时、拦截或接口限制影响 | 稍后重试，并对照其他来源     |

## 网站连通与出口：检查响应和分流

入口：**网络检测 → [网站连通与出口](https://ip.huzhihui.com/network/connectivity)**。

知道公网出口的含义后，接下来把范围缩小到具体网站。这个页面把两类结果放在一起：连通检测观察请求是否有响应，出口检测观察可读取的来源地址。

比如，我们希望某个目标经过代理。它能打开，只能说明这次访问可用；还要对照出口，才能进一步判断路径是否符合设置。

### 先检查网站是否响应

1. 打开页面，找到要观察的网站分组。
2. 滚动到对应区域，等待测试记录逐步填充。
3. 查看每个目标的延迟和测试记录。
4. 若要复测，使用对应分组的“重新测试”，保持网络设置不变，比较两次结果。

当前网站连通表格会展示一组多次测试记录。等待中的记录与失败记录不同：等待表示还没有完成，失败表示那一次没有成功取得探测结果。先等这一轮结束，再判断是否持续失败。

延迟先比较同一个目标在同样条件下的变化。例如同一浏览器访问同一目标，多轮结果经常在几十毫秒与几秒之间跳动，就值得继续检查网络波动。不要直接拿两个网站的数值给整条线路排名，它们的资源、距离和响应策略都可能不同。

### 再确认出口是否符合你的配置

假设你的目标是“国内网站直连，AI 网站经过代理”，可以照着做：

1. 在当前配置下，记录可读取出口的目标及其地址。
2. 到代理软件中确认当前使用的模式和规则。
3. 只调整你想检查的那一条规则或对应策略。
4. 返回 One IP 重新检测，必要时刷新页面。
5. 对比目标出口有没有按预期变化，再实际打开目标网站确认。

下面是**说明判断方法的假设示例，不是实测数据**：

| 目标       | 修改前     | 修改后     | 这说明什么                   |
| ---------- | ---------- | ---------- | ---------------------------- |
| 普通网站 A | 直连出口 A | 仍是出口 A | 这次调整没有改变它的可见出口 |
| AI 网站 B  | 直连出口 A | 代理出口 B | 该目标的出口发生了预期变化   |
| 网站 C     | 暂不可用   | 暂不可用   | 没有足够数据判断它走哪条路径 |

如果预期只有一个目标变化，结果所有目标都变了，先检查是否切到了全局代理。如果目标始终没变，检查域名是否匹配了预期规则，以及浏览器是否实际使用了该代理。One IP 负责展示检测结果，不会替你修改代理设置。

### “暂不可用”是否意味着网站打不开

不一定。检测请求与完整网页访问不是完全相同的操作。浏览器安全限制、防护页面、扩展拦截或目标不提供可读取信息，都可能影响检测。

这里的“跨域限制”可以简单理解为：浏览器允许打开一个网站，不代表允许另一个网页读取它的响应内容。

遇到这种结果，下一步是直接打开目标网站测试。若目标可以正常使用，只是 One IP 读不到出口，就把这一项理解为缺少检测数据，不用为了让它变绿反复修改网络。

## IP 检测：查看地址归属与信誉

入口：**网络检测 → [IP 检测](https://ip.huzhihui.com/network/ip)**。

### 基本用法：查询当前出口或指定地址

1. 找到 IP 搜索框；若当前页面收起了搜索，先展开搜索。
2. 输入一个 IPv4 或 IPv6 地址。例如 `1.1.1.1` 可以用来练习输入格式。
3. 提交查询，等待详情返回。
4. 先核对结果中的地址，再查看归属、网络分类和信誉信息。
5. 已经查过的地址可以从“最近查询”中选择；需要最新结果时重新发起查询。

只填地址，不填网页链接。例如输入 `1.1.1.1`，不要输入 `https://1.1.1.1/path`。查询网站的注册信息请使用后面的 WHOIS 工具。

### 从地址归属到网络分类

首先看 **IP 是否正确**，再看 **国家或地区、ISP、ASN**，最后看分类和信誉。

地图只是帮助理解数据库给出的归属位置，不是手机定位。国家、城市、注册机构和实际使用地点也不总是一一对应。多个来源不一致时，先保留差异，不要直接挑一个喜欢的结果当结论。

住宅、移动网络、数据中心等标签描述的是数据源对地址的分类；VPN、代理、Tor 等标签也是线索。一个地址被标记为数据中心，并不表示它已经出故障；没有代理标签，也不保证目标平台一定把它看作普通家庭网络。

### 信誉分怎么看

IP 健康度接口的分数范围是 0–100，越高表示接口根据可用数据给出的信誉评价越好。项目将有效分数整理成以下状态：

| 分数                 | 英文状态   | 中文理解                 |
| -------------------- | ---------- | ------------------------ |
| 75–100               | `good`     | 信誉较好                 |
| 大于等于 45、小于 75 | `moderate` | 中等，需要结合其他信息   |
| 大于等于 0、小于 45  | `poor`     | 信誉较差，值得进一步核对 |
| 没有有效分数         | `unknown`  | 未知，暂时无法评价       |

例如显示 80 分，只能说明本次数据源评价落在 `good` 区间，不表示网速是 80，也不表示有 80% 的概率通过某个平台验证。信誉分不等于 ChatGPT、Claude 或其他服务的官方风控结果。

普通使用者可以把它作为补充信息：先确认目标能否使用，再结合分类和信誉排查，没必要为了一个分数不断更换出口。

## 全球 Ping：从不同地区检测同一个目标

入口：**网络检测 → [全球 Ping](https://ip.huzhihui.com/network/ping)**。

### 测量的是哪一段网络

前面的检测主要围绕当前浏览器。如果想知道同一个目标从其他地区访问起来怎么样，就需要换一个观察位置。

Ping 的基本思路是发出探测消息，再统计回应所需的时间。One IP 使用 Globalping 的远程探针完成这一步，探针就是部署在不同地方、负责执行测量的机器。

所以，你坐在上海，选了东京探针，测量的也是“东京探针到目标”的路径，而不是“你的电脑到目标”的路径。

### 基本用法：选择目标与探测地区

1. 在输入框填写目标 IP 或域名，例如 `1.1.1.1` 或 `example.com`。
2. 第一次先使用全球检测或一个区域，不必直接选择所有城市。
3. 想比较特定位置时，打开“自定义地区”，搜索国家或城市，选择后使用所选地区。
4. 点击“开始”，等待不同节点分批返回。
5. 查看结果中的地区、延迟和丢包信息；不需要继续时可以“停止检测”，保留已经返回的结果。

只输入 IP 或域名，不需要附带网页路径。优选模式适合先做大致比较，完整覆盖会使用更多探测地区和额度，确有需要时再选择。

### 结果怎么看

- **延迟**：这条探针到目标路径上的往返耗时，先比较同一目标的不同探针。
- **丢包**：发出的探测中，有多少没有收到回应。少量测试里的偶发丢包要复测，不能只看一次就确定长期不稳定。
- **超时或没有数值**：可能是网络问题，也可能是目标不响应这种探测。
- **部分测量未完成**：先查看已经返回的节点，不要把所有未返回节点都当成目标故障。

有些目标会限制 ICMP，也就是 Ping 常用的探测方式。这时网页可能仍然可以打开。因此，全球 Ping 适合补充“不同地区的访问差异”，判断当前浏览器是否好用，仍要回到网站连通和实际访问。

## DNS、CDN 与域名信息查询

网络排查还会遇到几类看起来相近的信息：域名由谁解析、请求到了哪个节点、资源登记在谁名下。它们对应不同环节，我们按用途分别来看。

### DNS 出口：谁在帮你解析域名

入口：[DNS 出口](https://ip.huzhihui.com/network/dns)。

我们输入 `ip.huzhihui.com` 时，浏览器需要先获得连接目标所用的地址。DNS 负责帮助完成这一步，可以把它理解为根据名称查地址的过程。

因此，网站访问不符合预期时，除了查看网页出口，也可以检查解析请求体现出的路径。

打开页面后，等待检测返回，观察解析出口及其网络归属。要比较配置，可以先记录结果，再只更改安全 DNS 或代理的解析设置，然后重新检测。

如果 DNS 出口与网页出口属于不同地区，先检查浏览器是否启用了独立的安全 DNS、代理是否使用远程解析。它们经过不同服务时，结果可能不同，不能只凭地区不一致就确定“泄漏”。

这个页面显示的是检测过程观察到的解析出口，不一定就是你在系统网络设置里手动填写的 DNS 地址。存在中转解析时，两者可能不同。

### CDN 节点：这次请求碰到了哪个边缘节点

入口：[CDN 节点](https://ip.huzhihui.com/network/cdn)。

CDN 可以理解为分布在不同地方的服务节点。网站使用它来提供内容或转发请求，访问同一服务时，不同网络可能连接到不同节点。

1. 打开页面，查看对应厂商的检测结果。
2. 展开被省略的节点或响应信息，阅读可获得的详情。
3. 如需比较线路，记录当前结果，再切换一个网络条件后复测。

节点标识和缓存字段来自服务愿意公开的信息，某些字段可能没有返回。它们适合帮助理解当前请求路径，不直接等于网站源服务器的位置，也不能单凭某个节点代号判断线路优劣。

### WHOIS：查域名、IP 或 ASN 的注册资料

入口：[WHOIS](https://ip.huzhihui.com/network/whois)。

WHOIS 页面通过 RDAP 读取注册资料，可以理解为查询网络资源的登记信息。

1. 输入域名、IP 地址或 AS 号，例如 `example.com`、`1.1.1.1`、`AS13335`。
2. 提交查询，等待结果返回。
3. 查看登记机构、资源范围、相关日期、状态和实体信息，具体字段取决于查询对象。
4. 有疑问时再查看原始响应，不需要一开始就读原始数据。

查询域名时不必加 `https://` 或文章路径。域名到期时间是注册层面的信息，不是网站停机时间；登记机构也不一定是网站实际运营者。资料被隐私保护或数据源没有公开时，部分内容为空很正常。

### 子域名查询：查公开证书里出现过的名称

入口：[子域名查询](https://ip.huzhihui.com/network/subdomains)。

以 `example.com` 为例，`www.example.com`、`api.example.com` 都是它下面的子域名。这个工具查询证书透明度日志，也就是公开证书留下的记录。

1. 输入要查询的域名，例如 `example.com`。
2. 发起查询，等待证书日志返回。
3. 查看结果列表，数量多时翻页，可以复制单条或“复制全部”。

结果表示名称曾经出现在相关证书记录中，不保证现在还在使用，也不保证能打开。没有发现记录，同样不代表这个域名没有子域名。

## AI 检测：从网络响应到实际使用

入口：[AI 检测](https://ip.huzhihui.com/ai/)。

### 基本用法

先选定一个正在出问题的平台，完成下面这一轮检查。不要同时调整多个平台的设置，否则很难比较结果。

1. 打开 AI 检测，找到你正在使用的平台，例如 ChatGPT、Claude 或 Gemini。
2. 等待资源探测返回，查看目标域名、延迟及可获得的出口信息。
3. 进入对应平台详情，查看更具体的检测与快捷入口。
4. 到“服务状态”核对是否有相关故障。
5. 最后实际打开该平台，尝试你原本失败的操作，例如登录或发送一条消息。

不是所有平台都能返回可读取的出口。没有出口数据时，不要拿别的平台或旁边的对照地址替代。对照结果只说明那一次对照请求的路径。

### 三种常见情况

**有延迟数值，但无法聊天。** 说明某个被测资源有响应，不代表登录、验证码、订阅、额度或模型请求都能成功。继续看目标页面的实际报错，并核对官方服务状态。

**One IP 探测失败，但目标网站能用。** 可能是被测资源、跨域规则或浏览器拦截影响了检测。以实际使用情况为补充，不必为了一项探测修改原本可用的配置。

**多个 AI 目标和其他网站一起失败。** 先回到基础网络与代理检查。如果普通网页也打不开，应先恢复网络，再排查单个平台。

各平台的网页、API 和不同产品可能是不同服务。尤其是状态链接指向 API 产品时，要看清楚它对应的范围，不能把 API 正常直接理解成聊天网页一定正常。

## 浏览器检测：环境、指纹与权限

前面几组工具主要检查请求路径和服务响应。接下来再看浏览器本身。

一个常见场景是：同一台电脑、同一条网络，换个浏览器就能正常使用。这时网络未必是主要原因，我们可以从环境信息开始，再根据现象检查指纹、扩展和权限。如果所有设备都无法联网，仍应先回到网络检测。

### 环境信息：看看浏览器对外提供了什么

入口：[环境信息](https://ip.huzhihui.com/browser/environment)。

进入页面后，查看系统、浏览器、语言、时区、屏幕和硬件相关信息。文字放不下时打开详情阅读。

第一次只需要核对：系统是否符合实际、语言和时区是否符合自己的设置、屏幕信息是否与当前窗口环境相符。浏览器可能为保护隐私而减少或修改可读取信息，因此它不是完整的电脑硬件检测报告。

例如人在中国使用海外代理，IP 显示海外、时区仍是中国，并不矛盾：前者描述网络出口，后者来自设备环境，不需要为了让它们相同而随意修改系统。

### 指纹检测：比较浏览器环境有没有变化

入口：[指纹检测](https://ip.huzhihui.com/browser/fingerprint)。

这里先解释一下“指纹”。浏览器会提供语言、屏幕、字体及绘图能力等信息，指纹算法将一组特征整理成结果，再生成摘要编号，也就是页面里的指纹 ID。

我们使用它，主要是为了比较环境变化。比如调整一个扩展前后，哪些组成项目发生了变化，结果 ID 是否也随之改变。

1. 进入页面，等待首次检测完成。
2. 记录所选算法及结果 ID，查看组成项目。
3. 保持同一个浏览器、同一种算法，重新检测一次，观察结果是否变化。
4. 若要排查扩展影响，每次只调整一个扩展，再对比相同算法下的结果与项目详情。

不同算法的编号本来就不应直接比较。浏览器升级、字体、隐私模式或设置变化，也可能改变结果。编号相同不证明是同一个人，编号变化也不意味着账号一定会被平台限制。

当前页面还提供 JA3/JA4 Fingerprint 选项。这类信息描述连接建立时的 TLS 特征，与网页通过 JavaScript 采集的环境指纹不同。TLS 可以简单理解为 HTTPS 建立加密连接的过程。普通用户不需要据此做设置；显示“平台未提供”时，只表示当前没有得到对应字段。

### 环境一致性：寻找值得核对的差异

入口：[环境一致性](https://ip.huzhihui.com/browser/consistency)。

页面会自动开始本地深度检测，等待完成后先看整体结果，再打开具体模块详情。需要复测时使用重新检测；离开页面会清理当前检测。

一致性检查是在比较不同接口返回的信息是否存在需要注意的差异。请按下面的方式读结果：

| 结果               | 含义                               | 建议操作                                   |
| ------------------ | ---------------------------------- | ------------------------------------------ |
| 发现需要核对的信号 | 某些信息存在差异或特殊表现         | 打开详情看具体项目，结合扩展及隐私设置判断 |
| 无法检测、读取错误 | 本次检测没有完成或浏览器不允许读取 | 先确认权限和兼容情况，再考虑复测           |
| 未发现异常信号     | 本次成功执行的检查没有报告异常     | 保留结果，不把它当成所有网站都认可的证明   |

例如，启用了防指纹保护的浏览器可能有意改变某些信息。看到信号后，先判断是否与你自己的设置有关，不需要把所有隐私保护关闭来追求一个“全绿”结果。

深度检测基于项目中的 CreepJS 模块，本地实现的范围与官方完整站点不同，也不包含官方联网评分和 Worker 检测。多个模块可能指向同一个原因，不能把报告条数直接当成独立故障数量。

### 自动化特征：查看线索，不直接判断真人或机器人

入口：[自动化特征](https://ip.huzhihui.com/browser/automation)。

打开页面查看项目详情，关注到底是哪一个可观察信号触发了提示。它不是账号风控测试，也不能覆盖所有自动化工具。

如果没有使用自动化工具却看到提示，可以在相同网络下，用另一个正常浏览器作对照，再逐项排查扩展或环境设置。这里先关注提示对应的具体项目，再判断它是否与当前使用问题有关。

### 权限与隐私：检查摄像头、麦克风、定位和 WebRTC

入口：[权限与隐私](https://ip.huzhihui.com/browser/privacy)。

例如，视频通话页面打不开摄像头，就可以从这里检查权限。页面显示的状态可能是已允许、已拒绝、需要询问，或者浏览器无法提供状态。

需要注意的是，网站权限和系统权限是两层设置。浏览器允许某个网站使用摄像头后，操作系统仍可能阻止浏览器访问设备，所以还要结合实际测试。

需要测试摄像头、麦克风或定位时，点击对应功能，再阅读浏览器弹出的权限提示。只测试当前需要的项目即可；不使用这些功能，不必授权。当前媒体权限测试在获取媒体流后会关闭，不进行音视频录制。

如果曾经点过拒绝，浏览器可能不会再次弹窗。可以打开地址栏旁的站点权限设置，检查对应权限；必要时再检查操作系统的隐私权限，然后重新测试。

WebRTC 是浏览器实时音视频通信使用的技术之一。它的连接路径可能与普通网页请求不同。查看检测地址时，将它与 HTTP 出口对照：结果不同，说明值得核对网络配置，但还要区分公网地址、内网地址以及浏览器隐藏地址后的表现，不能看到任何差异就直接断定泄漏。

### 人机校验：体验本站的一次验证

入口：[人机校验](https://ip.huzhihui.com/browser/challenges)，该入口需要服务端配置满足条件才会显示。

进入后等待自动验证，查看 Turnstile 状态及 reCAPTCHA v3 结果。失败或等待超时后可按页面提示重试；不要连续高频刷新。

reCAPTCHA v3 返回 0–1 范围的分数，本站当前通过阈值为 0.50。它与 IP 健康度的 0–100 分完全不同。这里通过了，仅表示本站这一次验证达到本站条件，不保证在其他网站也会通过。

看不到入口、提示未配置或平台不可用时，可能是站点配置或服务商限制，不需要因此修改自己的 IP。

## 服务状态：核对厂商的故障与维护

入口：[服务状态](https://ip.huzhihui.com/status/)。

1. 找到出问题的平台或服务。
2. 查看当前状态、更新时间，以及是否有故障或维护事件。
3. 打开事件详情，确认影响的是哪个产品、组件或地区。
4. 如有官方事件链接，继续阅读厂商说明与处理进度。

“降级”通常表示服务仍可能运行，但速度或部分功能受影响；“故障”表示有功能不可用；“维护”表示正在进行计划内操作。仍要以对应事件描述为准。

如果事件明确影响你正在使用的功能，而且时间也对应，就可以先等待恢复，避免反复调整本地配置。若厂商显示正常，但只有自己失败，则继续检查网络、浏览器和账号。

官方状态也可能晚于实际故障更新。“没有公告”和“所有用户一定正常”不是一回事；One IP 没读到状态时，也不能替厂商判定正常。

## 常见问题与排查思路

### 开了代理，为什么 IP 还是没变

1. 确认代理软件已经连接，并记下当前模式。
2. 到“网站连通与出口”看具体目标，而不是只看概览中的一个来源。
3. 如果规则规定这个目标直连，出口不变可能符合预期。
4. 如果规定经过代理，检查该域名的规则命中与浏览器代理设置。
5. 只修改相关配置，再刷新复测，最后直接访问目标验证。

### 普通网页正常，AI 平台不能用

1. 到 AI 检测查看该目标的响应情况。
2. 核对可读取的出口是否符合预期。
3. 到服务状态查看对应产品的事件。
4. 直接打开目标平台，记录是登录失败、验证码失败、额度不足，还是发送消息失败。
5. 如果同一网络下另一个浏览器可用，再查原浏览器的扩展、权限和环境。

这几种报错属于不同环节，求助时保留原始错误文字，比只说“不能用”更容易定位。

### 浏览器和终端查到的 IP 不一样

先看浏览器是不是用了代理扩展，再看终端是否配置了代理。浏览器扩展通常不意味着所有程序都经过同一出口。用同一网络路径比较之后，再判断是否异常。

### 浏览器检测出现多项异常

先打开具体详情，区分“发现差异”和“检测失败”。然后保持网络不变，用另一个正常浏览器对照。若只有一个浏览器出现问题，再逐项检查扩展及隐私设置，不必一次重置全部配置。

### 检测长时间等待或大量失败

1. 先打开其他常用网站，确认设备能够正常上网。
2. 等当前检测结束，不要同时开很多标签页反复测试。
3. 若页面提示请求过多，暂停一段时间再试。
4. 只切换 Wi-Fi 或手机流量其中一个条件，判断是否与当前网络有关。
5. 若其他网页正常、One IP 仍持续异常，记录时间、页面地址和错误信息后反馈。

### 换了节点，页面仍显示旧结果

先确认当前展示的是查询历史还是刚刚请求的结果。最近查询可能保留此前成功查询的数据，需要重新提交来更新。再确认当前检测已完成，必要时刷新页面。对比时记录检测时间，避免把旧结果和新结果混在一起。

## API 接入：在服务器上调用并返回结果

API 可以直接用于 Linux 服务器、定时脚本、后端服务和桌面工具，不需要打开网页，也不需要登录或 API Key。常见用途是确认服务器当前出口，查询某个公网 IP 的归属与健康度，或者把查询结果接入自己的系统。

下面按“直接请求 → 读取字段 → 服务端集成 → 向前端返回结果”的顺序说明。完整接口约定以本站的 [API 接入文档](https://ip.huzhihui.com/docs/api)为准。

### 接口地址与返回格式

如果只想拿到 API 结果，直接访问下面的地址即可。浏览器打开会显示数据，程序发送 GET 请求会收到同样格式的响应，不需要从网页中提取内容。

| 想得到什么                     | 可直接访问的 API 地址                                                                                                        | 成功时的返回格式 |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | ---------------- |

| `ip`     | 否       | 要查询的公网 IPv4 或 IPv6；省略时查询本次请求的出口 | `1.1.1.1`、`2606:4700:4700::1111` |
| `format` | 否       | `json` 或 `text`，默认 `json`                       | `format=text`                     |

成功的 JSON 响应使用 `application/json`，文本响应使用 `text/plain; charset=utf-8`。程序接入建议使用默认 JSON；`format=text` 适合人直接阅读，不建议再从文本中按行提取字段。

### 先分清：查询服务器出口，还是查询指定 IP

这是服务端接入时最容易用错的地方。**省略 `ip`，查的是发出这次请求的程序所使用的公网出口。**

| 在哪里调用                                | 不传 `ip` 时查询谁                           |
| ----------------------------------------- | -------------------------------------------- |
| 本机终端                                  | 终端请求使用的出口                           |
| 云服务器 SSH 终端                         | 云服务器请求使用的出口                       |
| 容器或后端进程                            | 该进程通过宿主机、NAT 或代理访问接口时的出口 |
| 浏览器直接打开 API 地址                   | 浏览器这次请求使用的出口                     |
| 浏览器请求自己的后端，再由后端调用 One IP | 自己的后端出口                               |

例如，用户在上海访问你的服务器，服务器在新加坡。服务器调用 `/api/ip/health` 而不传参数，得到的是服务器这次请求的出口信息；API 不会自动知道上海用户的地址。

如果业务需要查询访客 IP，应由自己的后端根据连接信息和**已配置的可信反向代理**确定访客地址，再通过 `ip` 参数查询。不要直接信任客户端随意提交的 `X-Forwarded-For`，也不要尝试把访客地址塞进请求头来改变 One IP 对调用方的识别。

显式传入 `ip=1.1.1.1` 只是查询该地址的数据，不会把服务器出口切换成它，也不会测量这个地址访问 ChatGPT、Claude 或其他网站的实际连通性。

### 在服务器终端调用：curl 示例

先通过 SSH 登录需要检查的服务器，再在它的终端执行命令。macOS、本地 Linux 也可以执行；旧版 Windows PowerShell 可以把 `curl` 写成 `curl.exe`，避免同名别名。

**1. 查询服务器本次请求的出口。**

```bash
curl -sS --connect-timeout 5 --max-time 15 \
  'https://ip.huzhihui.com/api/me'
```

只取出口 IP，需要额外安装 `jq`：

```bash
curl -fsS --connect-timeout 5 --max-time 15 \
  'https://ip.huzhihui.com/api/me' | jq -r '.ip'
```

**2. 查询服务器出口的健康度，直接返回文本。**

```bash
curl -sS --connect-timeout 5 --max-time 15 \
  'https://ip.huzhihui.com/api/ip/health?format=text'
```

**3. 查询指定公网 IPv4，直接返回 JSON。**

```bash
curl -sS --connect-timeout 5 --max-time 15 \
  'https://ip.huzhihui.com/api/ip/health?ip=1.1.1.1'
```

**4. 查询指定公网 IPv6。** 使用 `--get` 和 `--data-urlencode` 生成查询字符串，避免手动拼接参数：

```bash
curl -sS --connect-timeout 5 --max-time 15 --get \
  'https://ip.huzhihui.com/api/ip/health' \
  --data-urlencode 'ip=2606:4700:4700::1111' \
  --data-urlencode 'format=json'
```

`-sS` 隐藏进度条但保留连接错误；`--connect-timeout 5` 限制建立连接的时间；`--max-time 15` 限制整次请求的时间。URL 两侧的引号要保留，否则 Shell 可能把参数里的 `&` 当作后台运行符。

需要比较 IPv4 和 IPv6 出口时，可以分别给查询当前出口的命令添加 `-4`、`-6`。这两个选项改变的是访问 API 的连接协议；`ip=` 改变的是查询目标，两者作用不同。服务器没有 IPv6 路由时，`-6` 请求失败不能解释为某个目标 IP 的健康度差。

### JSON 返回什么，程序该读哪一层

健康度接口成功时直接返回字段对象，没有外层的 `data` 或 `result`。下面是**结构示例**，用 `null` 演示缺少数据的情况，不代表 `1.1.1.1` 的实时结果：

```json
{
  "ip": "1.1.1.1",
  "checked_at": "2026-10-15T00:00:00Z",
  "score": null,
  "status": "unknown",
  "country": null,
  "region": null,
  "city": null,
  "isp": null,
  "asn": null,
  "flags": {
    "residential": null,
    "datacenter": null,
    "mobile": null,
    "vpn": null,
    "proxy": null,
    "tor": null,
    "crawler": null,
    "abuser": null
  }
}
```

因此 JavaScript 中读取的是 `data.ip`、`data.score`，而不是 `data.data.ip`。`/api/me` 也是直接返回对象，但字段集合不同，不包含健康度的 `score`、`status`、`flags`，部分归属字段也可能缺失。

| 健康度字段                  | 含义                                                     | 接入时注意                             |
| --------------------------- | -------------------------------------------------------- | -------------------------------------- |
| `ip`                        | 本次查询的地址                                           | 先核对查询目标                         |
| `checked_at`                | 本次生成响应的时间                                       | 不代表全部数据源都在此刻更新           |
| `score`                     | 0–100 的信誉分                                           | `null` 表示没有有效分数，不能转成 0    |
| `status`                    | `good`、`moderate`、`poor`、`unknown`                    | 这是健康度评价，不是 HTTP 请求是否成功 |
| `country`、`region`、`city` | 国家、区域、城市                                         | 数据库归属，不是 GPS                   |
| `isp`、`asn`                | 网络服务提供方与自治系统编号                             | 可能为 `null`                          |
| `flags`                     | 住宅、数据中心、移动网络、VPN、代理、Tor、爬虫与滥用标记 | 每个值都可能是 `true`、`false`、`null` |

`true` 表示肯定标记，`false` 表示否定标记，`null` 表示未知。判断时保留这三种状态，不要用 `Boolean(value)` 把 `null` 变成 `false`。HTTP 200 且 `status: "unknown"` 表示请求成功但缺少评价数据；它和请求超时、HTTP 429、HTTP 503 是不同情况。

### 服务器调用：用 Node.js 读取 JSON

使用支持内置 `fetch` 的 Node.js，下面示例按 Node.js 22 及以上编写，无需安装第三方依赖。保存为 `lookup-ip.mjs`：

```js
const url = new URL('https://ip.huzhihui.com/api/ip/health');
const targetIp = process.argv[2];

if (targetIp) url.searchParams.set('ip', targetIp);

try {
  const response = await fetch(url, {
    signal: AbortSignal.timeout(10_000),
  });
  const body = await response.text();

  if (!response.ok) {
    const retryAfter = response.headers.get('retry-after');
    throw new Error(
      `HTTP ${response.status}: ${body}` +
        (retryAfter ? `; Retry-After: ${retryAfter}` : ''),
    );
  }

  const data = JSON.parse(body);
  console.log(JSON.stringify(data, null, 2));
} catch (error) {
  console.error(error);
  process.exitCode = 1;
}
```

在服务器上执行：

```bash
# 不传参数：查询这个 Node.js 进程请求使用的出口
node lookup-ip.mjs

# 传入参数：查询指定地址
node lookup-ip.mjs 1.1.1.1
node lookup-ip.mjs 2606:4700:4700::1111
```

这里先检查 `response.ok`，再解析成功数据。`fetch` 收到 400、429、503 仍然会返回一个响应对象，不能只依赖 `catch` 发现 HTTP 错误。读取错误正文可以保留 API 给出的具体原因；10 秒超时则用于避免脚本一直等待。内置接口用法可参考 [Node.js fetch 文档](https://nodejs.org/api/globals.html#fetch)。

需要接入业务时，在解析后读取 `data.ip`、`data.score`、`data.flags.vpn` 等字段即可。不要仅凭分数或某个标记就认定账号一定安全、AI 平台一定可用。

### 服务器调用：用 Python 读取 JSON

Python 3 可以直接使用标准库，不需要安装 `requests`。保存为 `lookup_ip.py`：

```python
import json
import sys
from urllib.error import HTTPError, URLError
from urllib.parse import urlencode
from urllib.request import Request, urlopen

url = "https://ip.huzhihui.com/api/ip/health"
if len(sys.argv) > 1:
    url += "?" + urlencode({"ip": sys.argv[1]})

request = Request(url, headers={
    "Accept": "application/json",
    "User-Agent": "OneIP-Server-Example/1.0",
})

try:
    with urlopen(request, timeout=10) as response:
        data = json.load(response)
    print(json.dumps(data, ensure_ascii=False, indent=2))
except HTTPError as error:
    body = error.read().decode("utf-8", errors="replace")
    print(f"HTTP {error.code}: {body}", file=sys.stderr)
    retry_after = error.headers.get("Retry-After")
    if retry_after:
        print(f"Retry-After: {retry_after}", file=sys.stderr)
    sys.exit(1)
except (URLError, TimeoutError) as error:
    print(f"请求失败：{error}", file=sys.stderr)
    sys.exit(1)
```

```bash
# 当前 Python 进程请求使用的出口
python3 lookup_ip.py

# 指定 IPv4 / IPv6
python3 lookup_ip.py 1.1.1.1
python3 lookup_ip.py 2606:4700:4700::1111
```

`Request` 显式声明接收 JSON，并用 `User-Agent` 标识示例程序；接入时可以改成自己的真实应用名称。`urlencode` 负责参数编码，`timeout=10` 限制阻塞网络操作的等待时间。`HTTPError` 要在 `URLError` 前处理，才能读取 API 返回的状态和错误正文。标准库行为可参考 [Python urllib.request 文档](https://docs.python.org/3/library/urllib.request.html)。

### 直接返回 API 结果：完整 Node.js 接口

如果自己的网页要读取结果，推荐让网页请求自己的后端，再由后端调用 One IP：

```text
你的网页 → 你自己的 /api/ip-health → One IP /api/ip/health
         ← 返回状态、正文和格式 ←
```

直接在浏览器地址栏打开 API，与在另一个网站的 JavaScript 中跨域读取 API，受不同的浏览器规则约束。One IP 的浏览器调用仅支持本站同源；自己的网页应通过后端接入，`mode: 'no-cors'` 得到的响应无法供 JavaScript 读取正文。

下面给出一个可以独立启动的后端接口。保存为 `ip-api-server.mjs`，使用 Node.js 22 及以上运行，无需安装 Express：

```js
import { createServer } from 'node:http';

const server = createServer(async (request, response) => {
  const input = new URL(request.url, 'http://localhost');

  if (input.pathname !== '/api/ip-health') {
    response.writeHead(404);
    response.end();
    return;
  }

  if (request.method !== 'GET') {
    response.writeHead(405, { Allow: 'GET' });
    response.end();
    return;
  }

  const url = new URL('https://ip.huzhihui.com/api/ip/health');
  for (const name of ['ip', 'format']) {
    if (input.searchParams.has(name)) {
      url.searchParams.set(name, input.searchParams.get(name));
    }
  }

  try {
    const upstream = await fetch(url, {
      signal: AbortSignal.timeout(10_000),
    });
    const body = Buffer.from(await upstream.arrayBuffer());
    const headers = {
      'Content-Type':
        upstream.headers.get('content-type') ?? 'application/json',
      'Cache-Control': 'no-store',
    };
    const retryAfter = upstream.headers.get('retry-after');
    if (retryAfter) headers['Retry-After'] = retryAfter;

    response.writeHead(upstream.status, headers);
    response.end(body);
  } catch (error) {
    console.error(error);
    const timedOut = error.name === 'TimeoutError';
    response.writeHead(timedOut ? 504 : 502, {
      'Content-Type': 'application/json; charset=utf-8',
      'Cache-Control': 'no-store',
    });
    response.end(
      JSON.stringify({
        error: timedOut
          ? 'One IP 请求超时'
          : '无法连接 One IP，请检查服务端日志',
      }),
    );
  }
});

server.listen(3000, '127.0.0.1', () => {
  console.log('API: http://127.0.0.1:3000/api/ip-health');
});
```

先启动服务：

```bash
node ip-api-server.mjs
```

再在同一台服务器的另一个终端测试：

```bash
# 查询自己的后端出口，返回 JSON
curl -sS 'http://127.0.0.1:3000/api/ip-health'

# 查询指定地址，返回 JSON
curl -sS 'http://127.0.0.1:3000/api/ip-health?ip=1.1.1.1'

# 原样返回文本
curl -sS 'http://127.0.0.1:3000/api/ip-health?ip=1.1.1.1&format=text'
```

这里的“直接返回”包括三件事：保留上游 HTTP 状态码，保留响应正文，保留 `Content-Type`；遇到限流时也保留 `Retry-After`。所以正常查询直接得到 JSON 或文本，无效参数仍然是 400，限流仍然是 429，不会被包装成 HTTP 200，也不会把 JSON 对象再次编码成带引号的字符串。只有后端自己连接失败或超时，才生成本地的 502 或 504。

例子只监听服务器回环地址。接入现有网站时，把这段处理逻辑放进现有后端，或让网站的反向代理将同源 `/api/ip-health` 转到该进程；浏览器中的 `127.0.0.1` 指向用户自己的电脑，不能把上面的测试地址直接当成线上接口地址。纯静态托管没有后端进程，需要另行部署服务。

前端在**已经配置好同源后端路由**的页面中调用：

```js
const response = await fetch('/api/ip-health?ip=1.1.1.1');
const body = await response.text();

if (!response.ok) {
  throw new Error(`HTTP ${response.status}: ${body}`);
}

const data = JSON.parse(body);
console.log(data.ip, data.score, data.status);
```

这个转发示例允许调用方选择查询目标，不会自动识别访客 IP。省略 `ip` 仍然查询后端出口；如果需要“我的访客 IP”接口，应由后端从可信连接信息中确定目标，再传给 One IP。前端调用如果选择 `format=text`，直接读取 `body`，不要再执行 `JSON.parse`。

### 错误、超时与限流怎么处理

排查时先查看 HTTP 状态和原始正文。给 curl 添加 `-i` 可以同时看到响应头：

```bash
curl -i -sS --max-time 15 \
  'https://ip.huzhihui.com/api/ip/health?ip=invalid'
```

这种无效参数会返回 HTTP 400，正文类似：

```json
{ "error": "请输入有效的公网 IPv4 或 IPv6 地址" }
```

| HTTP 状态码 | 常见含义                                                 | 处理方式                                       |
| ----------- | -------------------------------------------------------- | ---------------------------------------------- |
| 400         | IP 无效、非公网地址，或 `format` 不支持                  | 修正参数，不要原样重试                         |
| 403         | 跨源 `Origin` 被拒绝、边缘安全策略拦截，或访问被暂时限制 | 检查调用方式和错误正文；自己的网页通过后端调用 |
| 405         | 请求方法不支持                                           | 使用 GET                                       |
| 429         | 调用频率或额度超限                                       | 按 `Retry-After` 等待，降低频率与并发          |
| 502         | 网关、转发或数据获取异常                                 | 保留错误正文，检查服务端日志，稍后有限重试     |
| 503         | 无法识别公网出口，或服务、数据暂不可用                   | 根据错误正文处理；识别出口失败时可显式传 `ip`  |
| 504         | 网关或自己的后端等待超时                                 | 检查网络与超时设置，避免无限重试               |

即使请求了 `format=text`，错误正文也可能是 JSON。不要用“有没有 `score`”代替 HTTP 状态判断，也不要把超时、拒绝访问、限流或数据缺失转成 `score: 0`、`status: "poor"`。

站点安全层也可能返回纯文本或 HTML。例如 `403` 且正文包含 `error code: 1010`，表示客户端特征被安全策略拒绝，不是目标 IP 的信誉评价。Python 默认客户端在本次核对时遇到过这个响应，上面的显式请求头示例调用成功；若仍被拒绝，应保留时间、状态码和错误正文，联系站点排查。错误含义见 [Cloudflare 1010 说明](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1010/)。

脚本需要在 HTTP 错误时以非零状态退出并保留正文，可以将 `-sS` 改成 `-sS --fail-with-body`；旧版 curl 若不支持这个选项，可先用 `-i -sS` 查看响应。`-f` 也会让 HTTP 错误返回失败状态，但通常不保留错误正文。

公开接口按请求来源限流。多名访客经同一台后端转发，会共享该后端出口对应的限额，不能按每个访客分别估算额度。收到 429 后不要立即循环重试；`Retry-After` 可能是等待秒数或 HTTP 日期，按响应值安排下一次请求。相关格式可参考 [Retry-After 说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Retry-After)，当前额度以 [API 接入文档](https://ip.huzhihui.com/docs/api)为准。

### 哪些网页功能不能直接搬到服务器 API

对外接入使用这里列出的 `/api/me` 和 `/api/ip/health`。网页内部的完整 IP 报告、WHOIS、全球探测等接口可能需要浏览器会话，不应把开发者工具里抓到的请求直接当成稳定开放接口。

AI 连通性、网站分流、WebRTC 和浏览器指纹等功能还依赖用户的浏览器与网络环境。服务器调用 IP 健康度 API 得到的是地址资料，不能代替这些测量，也不会返回用户是否已登录或能否与 AI 正常对话的结论。

## 查询记录、数据与问题反馈

IP、WHOIS 等查询工具会在当前浏览器保存最近成功查询的记录，方便再次查看。主题、语言和部分显示偏好也会保存在本地。需要清除时，可以通过浏览器的站点数据管理删除本站数据；清除后这些历史和偏好会一起重置。

“保存在浏览器里”不等于检测过程完全离线。查询 IP 时，目标地址可能发送给对应数据源；检测网站连通时，目标服务会看到这次连接；全球 Ping 使用远程测量服务；地图和人机校验也可能加载第三方资源。

清除本地站点数据不会删除第三方服务或托管平台已有的记录。查询地址也可能出现在浏览器历史中。具体说明可以查看[隐私政策](https://ip.huzhihui.com/privacy)和[使用条款](https://ip.huzhihui.com/terms)。

反馈问题时，建议提供下面这些信息：

```text
出问题的页面：
检测时间及所在时区：
设备、系统和浏览器版本：
使用 Wi-Fi 还是手机流量，是否经过代理：
做了哪些操作：
预期看到什么：
实际看到什么，完整错误文字是什么：
换网络或换浏览器后的结果：
```

截图前遮盖公网 IP、精确位置和指纹标识。不要附带账号密码、Cookie 或接口密钥。若问题只出现在某个第三方网站，也一并说明直接打开该网站的结果。

## 结语

到这里，One IP 的主要功能就介绍完了。实际使用时，先选一个具体问题，再找到对应工具做检查：出口不符合预期，就看分流；某个平台不可用，就对照连通结果和官方事件；浏览器之间表现不同，再检查环境与权限。

这篇也作为网站的使用说明保留。后续页面或字段调整时，会继续在对应章节补充。排查过程中记下修改前后的结果，最后回到目标网站验证，就能把工具里的信息用到实际问题上。
