## 前言

排查网络问题时，我们经常需要打开几个不同的网站：先查公网 IP，再看代理分流，然后检查 AI 网站能不能访问。如果页面还是异常，又得回头看浏览器扩展、WebRTC 和权限设置。

我做 [One IP](https://ip.huzhihui.com/)，就是想把这些日常用到的检测放到一起。这篇文章按实际排查顺序整理用法：先确认请求从哪里出去，再看目标能否响应，最后结合服务状态和浏览器环境缩小范围。不需要先了解项目实现，能打开浏览器就可以跟着操作。

## 出口 IP：不同请求可以走不同的路

出口 IP 是目标服务看到的请求来源地址。家庭路由器、运营商网络、VPN、代理以及 IPv4 / IPv6 路由，都可能影响这个地址。

例如，国内网站直接连接，AI 网站经过代理，那么两个网站看到不同的 IP 是正常现象。即便同一个设备，浏览器 HTTP 请求和 WebRTC 请求也可能走不同路径。

One IP 的概览与分流页面用于比较这些差异。阅读结果时，先看探测目标，再看 IP，不要把某一个来源的结果当成整台设备唯一的公网身份。

建议这样排查：

1. 记录当前网络的探测结果。
2. 打开或切换代理，再重新检测。
3. 对比目标网站的出口是否发生预期变化。
4. 若只有部分网站没有变化，检查这些域名对应的分流规则。

举个分流排查的例子：我们希望普通网站直连，AI 网站经过代理。先记录两类目标的出口，再只修改一条分流规则并重新检测。如果普通网站保持原来的出口、AI 目标切换到预期出口，才说明这次测试中的分流表现符合预期。若两类目标一起变化，就需要检查是否启用了全局代理，或者规则实际匹配到了其他策略。

对比时还要固定浏览器和网络。同时切换 Wi-Fi、节点和浏览器扩展，即使结果发生变化，也很难判断是哪一步造成的。

显示“暂不可用”通常意味着没有拿到可读取的数据。跨域策略、防护页面、超时和浏览器拦截都可能导致这种情况，不能直接解释为网站不可访问。

## IP 详情：位置、ASN 和信誉分别在说什么

[IP 检测](https://ip.huzhihui.com/network/ip) 支持 IPv4 / IPv6 查询，集中展示数据源能够提供的位置、网络归属、注册信息和风险标记。

**位置**是 IP 数据库的归属估计，不是设备 GPS。不同数据源可能给出不同城市，地图上的坐标也不代表用户的精确住址。

**ISP**表示运营商或网络服务提供方。**ASN**是自治系统编号，用于识别网络路由的管理主体。ASN、注册机构、实际使用者和机房位置并不总是一一对应。

**住宅、数据中心、移动网络、VPN、代理、Tor 等标记**来自数据源分类。它们适合辅助判断，不能仅凭一个标签认定用户行为。

### 查询时先核对目标

在 IP 检测页输入待查地址，先确认结果中的 IP 与输入一致，再看归属和分类。查询当前出口和查询手动输入的地址是两件事：后者只是查看目标 IP 的资料，不表示当前设备正在使用它。

如果多个数据源给出的城市不同，可以继续对照国家、ASN 和运营商信息，不必只凭地图上的一个点判断代理配置是否正确。

### 信誉分怎么看

IP 健康度的信誉分范围为 0–100，越高越好：

| 分数         | 状态     |
| ------------ | -------- |
| 75–100       | good     |
| 45 至小于 75 | moderate |
| 低于 45      | poor     |
| 无有效分数   | unknown  |

这里的 API 使用 Net.Coffee 返回的信誉数据，并按上面的阈值整理状态；它不是网络测速，也不是任何 AI 平台的官方风控结果。高分不保证登录成功，低分也不代表账号一定被限制。数据缺失时应读作“未知”，而不是“没有风险”。

## 网站连通与全球 Ping：测量视角不同

网站连通检测从浏览器请求目标资源，测得的时间会受到 DNS、连接建立、TLS、缓存、目标服务器和网络路径影响。部分功能采用多轮采样与中位数来减少偶发抖动，具体以页面结果为准。

[全球 Ping](https://ip.huzhihui.com/network/ping) 则由 Globalping 的远程探针测量目标。选中哪个地区的探针，就相当于从那个位置观察网络，并不是从你的设备发包。

因此：

- 浏览器 HTTP 延迟不能与 ICMP Ping 数值直接等同。
- 远程探针访问顺畅，不代表本地访问也顺畅。
- Ping 不响应可能是目标限制 ICMP，不能单独证明网站被阻断。
- 比较结果时，应尽量保持目标、探针与测量条件一致。

如果只是想确认当前浏览器能否收到网站响应，先用网站连通。如果想定位地区差异，再用全球 Ping 补充证据。

## DNS、CDN 与 WHOIS 的用途

[DNS 出口](https://ip.huzhihui.com/network/dns) 帮助观察解析链路体现出的网络出口。解析器可能使用转发或 Anycast，看到的网络归属不一定等于用户设备的位置。

[CDN 节点](https://ip.huzhihui.com/network/cdn) 展示探测中可读取的边缘节点、响应头或缓存信息。不同服务暴露的信息不同，没有某个字段不代表没有使用 CDN。

[WHOIS 查询](https://ip.huzhihui.com/network/whois) 使用 RDAP 获取域名、IP 或 ASN 注册资料。这里的注册信息适合确认资源归属，不能用来反推当前网站服务器或用户的实际位置。

## AI 检测：网络响应与账号能力分开看

[AI 检测](https://ip.huzhihui.com/ai/) 汇总 ChatGPT、Claude、Grok、Perplexity、Gemini、DeepSeek、通义千问和 Kimi 的网络情况。

表格显示域名、出口 IP 和延迟，并按延迟排序。能读取出口的目标使用其公开响应；目前配置了 ChatGPT、Claude、Grok 和 Perplexity 的出口查询，实际能否成功仍受网络与跨域限制影响。其他平台没有对应的可读取接口时，显示“暂不可用”。

这里测的是站点资源，不会代替你登录账号，也不会验证订阅、额度或模型调用权限。即使某个资源返回很快，登录、验证码或对话接口仍可能失败。

进入平台详情页还能查看出口对照。对照地址用于说明其他请求的路径，不应当作该 AI 平台的真实出口。

## 浏览器检测：先理解信号，再判断原因

### 环境信息与指纹

[环境信息](https://ip.huzhihui.com/browser/environment) 展示浏览器能够读取的系统、语言、屏幕、硬件等属性。[指纹检测](https://ip.huzhihui.com/browser/fingerprint) 将部分信号组合成结果，便于比较环境变化。

指纹不是身份证。浏览器升级、字体、隐私设置、扩展和设备变化，都可能影响结果；不同设备也可能表现出相似特征。

### 环境一致性与深度检测

进入[环境一致性](https://ip.huzhihui.com/browser/consistency)页面会自动开始本地深度检测，也可以手动重新检测。离开页面会取消当前检测。

深度检测基于项目固定版本的 CreepJS 模块，在同源独立上下文中运行。它帮助发现不同 API 返回信息之间的差异，并提供模块详情。

几个常见结果需要区分：

- **发现需要核对的信号**：存在值得检查的差异，不等于已经确认伪装。
- **无法检测或读取错误**：可能是权限、浏览器能力或隐私限制，结果不完整。
- **未发现异常信号**：仅针对本次成功执行的项目，不是浏览器真实性或安全证明。

多个模块可能记录同一个原因，不能把模块数量直接当成独立问题数量。本地实现也不包含官方联网评分和 Worker 检测，不能拿它与官方完整站点逐项等同。

### 自动化、权限与 WebRTC

[自动化特征](https://ip.huzhihui.com/browser/automation)展示浏览器中可观察到的自动化相关信号。它只能提供线索，无法可靠判定所有自动化环境。

[权限与隐私](https://ip.huzhihui.com/browser/privacy)可以查看权限状态并测试设备能力。摄像头、麦克风和定位测试由点击触发，受浏览器授权控制；媒体权限测试取得流后立即关闭，不录制音视频。

WebRTC 检测会访问 STUN 服务，可能展示不同于 HTTP 请求的出口。若你使用代理，可以将结果与网站出口对比，再判断是否符合自己的网络配置。

## 服务状态：用官方事件核对本地异常

[服务状态](https://ip.huzhihui.com/status/)聚合厂商公开的运行状态与事件，将重大、严重故障排在前面，方便先关注影响较大的问题。

读状态时还要看事件涉及哪个产品、地区或组件，以及更新时间。厂商显示正常，不排除你的账号或本地网络有问题；厂商发生故障，也不代表所有产品都受影响。

建议在本地网络出现异常时同时查看官方事件链接。页面读取失败或待确认时，不应将其归类为正常。

## API：在终端里查询 IP 健康度

无需 API Key，接口为：

```text
GET https://ip.huzhihui.com/api/ip/health
```

查询本次请求的公网出口，默认返回 JSON：

```bash
curl -fsS 'https://ip.huzhihui.com/api/ip/health'
```

这里检测的是 **curl 这次请求** 的出口。浏览器使用代理扩展、终端没有配置代理时，两者可能得到不同 IP，这并不矛盾。我们需要先确认命令和浏览器是否走同一条网络路径，再比较结果。

终端文本与指定地址查询：

```bash
curl -fsS 'https://ip.huzhihui.com/api/ip/health?format=text'
curl -fsS 'https://ip.huzhihui.com/api/ip/health?ip=1.1.1.1'
curl -fsS 'https://ip.huzhihui.com/api/ip/health?ip=2606:4700:4700::1111'
```

`ip` 只接受公网 IPv4 / IPv6。省略时使用请求出口，经过代理时就是代理出口。本地开发无法直接识别真实访客地址，需要指定 `ip`。

返回字段包括 `ip`、`source`、`checked_at`、`score`、`status`、`country`、`region`、`city`、`isp`、`asn` 和 `flags`。风险标记包含住宅、数据中心、移动网络、VPN、代理、Tor、爬虫和滥用分类。缺失值使用 `null`；信誉分无效时 `status` 为 `unknown`。

| 状态码 | 含义                        |
| ------ | --------------------------- |
| 400    | 参数或 IP 不符合要求        |
| 403    | 浏览器跨站调用被限制        |
| 405    | 请求方法不支持              |
| 429    | 触发限流，降低频率后重试    |
| 502    | 上游数据请求失败或返回异常  |
| 503    | 无法识别访客出口，请指定 IP |

错误统一返回 JSON `{"error":"…"}`，即便请求了文本格式也是如此。接口适合终端和脚本，浏览器调用受同源限制。不要通过轮换 IP 绕过限流。

### 在脚本里读取结果

安装了 `jq` 后，可以只提取排查时关心的字段：

```bash
curl -fsS 'https://ip.huzhihui.com/api/ip/health?ip=1.1.1.1' \
  | jq '{ip, source, score, status, country, isp, asn, flags}'
```

`1.1.1.1` 只是指定地址的查询示例，不代表当前出口，也不预设它的信誉分。脚本处理结果时保留 `null` 和 `unknown`，不要把缺失分数转换成 0；否则会把“没有数据”错误地归为“信誉较差”。遇到 429 时降低调用频率，遇到 502 时等待上游恢复后再试。

## 数据与隐私

查询目标可能发送至对应的数据源；浏览器直接请求的网站能看到该连接的出口 IP。全球 Ping 使用远程测量服务，地图加载第三方地图资源，配置后的验证码功能会联系对应提供方。

主题、语言、提示偏好和查询历史保存在当前浏览器。查询历史按类别保留最近 10 条成功结果，可以通过清除本站数据删除；地址也可能留在浏览器历史中。

托管服务处理网络请求，服务端按 IP 限流。清除浏览器数据不会删除第三方或托管服务的记录。具体说明见[隐私政策](https://ip.huzhihui.com/privacy)与[使用条款](https://ip.huzhihui.com/terms)。

## 一套实用的排查顺序

遇到“网络正常但某个 AI 网站不能用”，可以按这个顺序缩小范围：

1. 看概览，确认基础公网出口和网络响应。
2. 看分流出口，确认目标域名是否走了预期路径。
3. 看 AI 检测，确认浏览器是否取得目标资源响应。
4. 看服务状态，核对厂商是否有匹配的故障事件。
5. 网络可用但页面仍异常时，再检查浏览器扩展、权限和环境一致性。
6. 最后到目标服务确认账号、地区、额度或模型权限问题。

如果需要向别人反馈问题，记录检测时间、目标域名、浏览器、网络类型，以及切换前后的结果即可。截图前遮盖公网 IP、具体位置和不需要公开的环境信息，这样既能保留排查线索，也能避免分享过多个人数据。

## 结语

到这里，One IP 里几类常用检测就串起来了。我们先用出口和分流确认请求路径，再用连通性和官方事件检查目标状态，最后看浏览器环境和账号侧的问题。每次只调整一个条件，再回到同一页面比较结果，通常比反复换节点更容易找到原因。
